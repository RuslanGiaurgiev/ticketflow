# TicketFlow — продажа билетов на мероприятия

Учебный проект: система продажи билетов на концерты и спектакли, построенная на микросервисах.

**Часть 1 (сейчас)** — архитектура, всё лежит в [`docs/`](docs/README.md).
**Часть 2** — реализация по этим документам.

## Почему тема подходит под условие

| Требование задания | Как это выглядит в TicketFlow |
|---|---|
| Что-то нельзя потерять или задвоить | **Место в зале** нельзя продать дважды. **Деньги** нельзя списать дважды или потерять (оплатил, а билета нет). **Билет** нельзя выпустить дважды или пропустить по нему двоих. |
| Процесс может сломаться посередине | Покупка — это цепочка «держим места → берём оплату у внешнего провайдера → подтверждаем места → выпускаем билеты → уведомляем». Любой шаг может упасть, когда предыдущие уже выполнены. |
| Нельзя сделать одним сервисом с одной БД | Оплата идёт через внешний платёжный провайдер, который не участвует в нашей транзакции. Проверка мест должна выдерживать пиковую нагрузку при старте продаж, а остальное — нет. Выпуск билетов и уведомления можно отложить, но нельзя потерять. |
